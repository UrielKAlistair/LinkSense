\begin{abstract}
A Wi-Fi client in overlapping coverage must select an access point (AP)
before it can directly measure the service that each AP would provide.
Signal strength describes link quality, but not contention or load, and may
therefore favor a nearby but congested AP. This project investigates whether a
client can make a better decision using only passive observations collected
before association, without probe requests or assistance from the network.
This report defines the experimental foundation of that investigation: a
controlled ns-3 simulator that creates multi-AP deployments, records decoded
frames and physical carrier-sense activity, and replays each fixed topology once per target AP, changing only the AP the candidate joins. Every replay
of a topology therefore shares one identical pre-association observation while
yielding its own measured throughput. The simulator separates physical-topology
randomness from radio randomness and produces a structured choice-set dataset.
Across
1500 choice sets, a gradient-boosted model over 35 passive features selects the
best AP in 93.4\% of cases, against 64.7\% for strongest signal strength and
86.7\% for a heuristic that also accounts for channel occupancy. Sequence
models over the same observation do not improve on this, and the report sets
out what a further iteration would need for the value of temporal structure to
become testable.
\end{abstract}

\section{Problem Formulation}
\label{sec:problem}

Throughput depends on channel contention, competing stations, transmission
rates, retries, and the airtime consumed by neighboring basic service sets.
Received signal strength reflects such effects poorly if at all. Those effects do,
however, leave traces a client can hear without transmitting: the frames
themselves, and the time the medium spends busy. This project asks whether such traces are enough:
\emph{can a client choose the AP that will provide the greatest throughput
using only what its radio can passively observe before association?}

Existing load-aware methods \cite{dely2014bestap,adame2021channel} make their
load estimate after association, from AP-provided reports, or from a network
controller. A client making its first choice has none of these: only beacons
and some data frames, in which AP distance and offered traffic appear only
through their effects.

Let $\mathcal{A}=\{a_1,\ldots,a_N\}$ be the APs in one deployment and let $O$
be the candidate station's passive observation before it joins any AP. If
$y_i$ is the throughput obtained after joining $a_i$, the desired decision is

\begin{equation}
    a^* = \underset{a_i\in\mathcal{A}}{\operatorname{arg\,max}}\; y_i,
\end{equation}

using a decision function whose inputs are derived only from $O$. 

We can tackle this problem either by creating a model that solely ranks the available choices 
to determine $a^*$, or by simply predicting the value of $y_i$ for each $a_i$.

We attempt both methods to learn of their efficacy in this project 
as both are possible with a simulated environment. In a live network however, only one 
$y_i$ is ever measurable: the station joins a single AP and observes that AP's throughput, while the values of $y_j$ for every AP it did
not join are counterfactual. The simulator recovers all $N$ values by replaying
the same scenario once per target AP, changing only the AP the candidate joins therefore 
granting every choice set in the generated data the true value of $a^*$.

One key assumption must be carefully verified in the simulated data: $O$ must be 
identical across all $N$ runs of a given scenario. 
If any part of the observation varied with the AP eventually joined, a decision function could reach the right answer 
through a simulation artifact rather than through the network. 

\section{Simulator Design and Assumptions}
\label{sec:sim}

The simulator is built on ns-3.45 and its Wi-Fi models \cite{ns3models}. The
choice set presented to the candidate station contains only APs discovered
during its passive scan.

\subsection{Simulation Environment}

The deployment is static and single-floor with no walls, the environment TGax
assumes for its indoor small-BSS scenario \cite{tgax2016scenarios}. 
All stations are immobile and remain at their seeded positions. 
Radios are homogeneous IEEE 802.11n devices at 5 GHz on 20 MHz channels 
with Minstrel-HT rate control \cite{ns3models}. 

Every radio is an ns-3 \code{SpectrumWifiPhy} attached to one shared
\code{MultiModelSpectrumChannel}, on which a log-distance loss (exponent 3.0,
with 46.6777 dB of reference loss at 1 m) is followed by Nakagami fading.

\code{SpectrumWifiPhy} is chosen over the simpler \code{YansWifiPhy} as the Yans model 
simulates exactly zero cross channel interference by treating each channel as 
an isolated layer. If \code{YansWifiPhy} is used, the channel occupancy given by CCA 
measurements becomes a really powerful signal for models in a way that does not reflect reality.
\code{SpectrumWifiPhy}, on the other hand, represents a transmission as a power spectral density 
shaped by the 802.11 transmit mask, so a neighbor one channel away deposits real power in a
receiver's band and registers in its carrier sense. 

\subsection{Count, Topology and Channel occupancy of APs}

Each scenario first draws 2, 3, 4, 6, or 8 APs. They sit on a triangular
lattice 20 m apart: TGax recommends ``$\sim$10--20 m inter AP
distance'' for its dense indoor scenarios \cite{tgax2016scenarios}. 
Two APs form a pair, three an equilateral triangle, and the
four, six, and eight AP cases fill two rows of two, three, and four with
alternate rows offset by half a spacing, so the nearest-neighbor distance
does not change as options are added. 

Finally, each AP draws a channel uniformly at random from channels 
36, 40, 44, and 48. Random assignment biases the data toward more in-channel 
contention and interference which could potentially make the problem harder than if 
we plan out the channels to be minimally interfering. However, TGax sets precedent
for random assignment across four channels in its enterprise scenario, and across 
the non-overlapping set in its residential one
\cite{tgax2016scenarios}, so this is the strategy adopted.

\subsection{Count, Topology of background STAs}

2, 3, or 4 background stations are drawn independently for each AP and the
draws are summed, amounting to a multinomial distribution. 

A quarter of scenarios spread the stations uniformly. 
The rest declare one or more APs as "hotspots" around which stations are clustered. 
Such mixing of uniform and deliberately clustered regimes follows common practice in WLAN studies
\cite{wong2018daga,zhang2020placement}, and is of particular import here because under uniform
load every AP is about equally busy and the problem we examine collapses heavily to signal
strength.

We draw the number of hotspots at random with fewer hotspots being more likely
and the count capped at $\lceil N_{\mathrm{AP}}/3\rceil$. The area around a hotspot AP,
a 10 m disc around it, is assigned a probability density 4 times that of non-hotspot 
areas. Each station's position is drawn from this distribution. 

\subsection{Association and Load of background STAs}

Each station associates with an AP based on how high the received power from it is. 
The received power value computed with the channel loss used in the simulator,
is perturbed with Gaussian noise of 5 dB standard deviation (as in \cite{tgax2016scenarios}). 
This is done so that stations do not form unrealistic Voronoi partitions. 

Every station then draws its own offered load, independently, from a log-normal
distribution with median 2.25 Mbit/s and shape 0.9, capped at 25 Mbit/s, for a
mean of 3.37 Mbit/s. Traffic volumes are log-normal rather than Gaussian
\cite{lognormal2020}, and the right skew is what puts most stations on a light
load and a few on a heavy one without needing a mixture. The quartiles span the
mix an AP actually carries, from voice and browsing up through
high-definition video.

\subsection{Placement of candidate STA}

The position where the candidate station is placed is drawn such that the
decision is often non-trivial: 70\% lands near a boundary between neighboring
APs, and 30\% at 4--16 m from a single AP. 

\subsection{Data Capture}

Background traffic starts at $t=0.5$ s. Each station's arrivals are Poisson at
its own data rate, and its first packet is delayed by a phase drawn uniformly
over one mean interval. Without that phase, stations sharing an AP and a rate
would transmit in lockstep for the whole run. The non-full-buffer models in the
TGax set randomize phase for the same reason \cite{tgax2016scenarios}.

Passive recording runs from $t=2$ s to $t=7.5$ s, covering 5.5 s of loaded
traffic. It starts 1.5 s after the traffic because Minstrel-HT needs about that
long to converge, and until it does every scenario carries the same opening
burst of retransmissions. This burst is a property of when the run started, not
of the deployment being observed.

The candidate associates at $t=8$ s, 0.5 s after recording ends. The gap is a
guard: ns-3 performs target-dependent polling shortly before a join, and
without it the scanners would capture that exchange. The recorded features
would then depend on which AP is being evaluated, leaking the label into the
observation.

After joining, the candidate offers 100 Mbit/s in 1250-byte packets until the
run ends at $t=20$ s. That rate keeps it backlogged, so its measured throughput
reflects the service the network gives it rather than the limit of its own
traffic generator.

\subsection{Matched Counterfactual Replays}

For each sampled topology and radio seed, the experiment runs once per target
AP. AP and station positions, background traffic, the candidate's position, and
every pre-association device stay fixed; only the AP selected at $t=8$ s
changes. A \code{topologySeed} fixes the deployment: station placement, channel
selection, and the load offered by each station. 

An independent \code{rngSeed} controls everything that varies between one occasion and
another --- fading, contention, rate adaptation, and the arrival times of the
background packets themselves. Three radio seeds are generated per topology. 

A station's demand is a property of the deployment; when its packets happen to
leave is not, so only the data rate belongs to the first seed.
Separating the two streams is what allows stochastic radio behavior to be
repeated without the physical deployment shifting underneath it. This provides
insight as to how much of the true answer is dependent purely on the
topological configuration of stations and APs and how much depends on the
random time evolution of the medium.

\section{Observation and Dataset Construction}
\label{sec:obs}

\subsection{Recording and Projection}

A deployed client scans across all channels that host APs in a rotating fashion.
The simulation records more than any deployed client can be expected to observe
by recording activity on every occupied channel simultaneously. We then project 
this complete record down to what a single scan would see.

Specifically, the candidate STA carries one receive-only scanner PHY per
occupied channel, plus a separate PHY reserved for association. The scanner
PHYs never transmit and never associate; the association PHY is parked on
unused channel 149 until the decision time. At $t=7.5$ s the scanner PHYs move to
the parking channel as well.

Two traces are recorded. The monitor-sniffer trace holds every frame a scanner
decodes, with time, frequency, BSSID, transmitter, frame category, beacon and
retry flags, length, RSSI, noise, airtime, and PHY rate. The PHY-state trace
gives the fraction of each 102.4 ms beacon interval in which carrier sense
marked the channel busy. This clear-channel-assessment (CCA) measurement
registers energy a frame-only view misses: interference, and transmissions too
distant to decode. 
Some driver stacks expose an equivalent channel-busy counter, 
though availability varies by platform.

The projection onto one passive radio is done as follows: 
One radio is assumed to rotate through the occupied channels in random order, 
dwelling 110 ms on each with 0.15 ms to retune, and repeats the cycle 
for as much of the window as it fits, so every channel is revisited many 
times before the decision. Frames and CCA intervals falling outside a 
dwell are discarded. A 110 ms dwell spans just over one 102.4~ms beacon 
interval, so each visit yields about one beacon from every AP on that channel. 
RSSI is then perturbed by uniform error within $\pm3$ dB and quantized to 1 dB. 
Both steps run after ns-3 from a recorded scan seed, so scan policy and 
measurement noise can be varied without repeating a simulation.

The recorded frame and channel-busy traces are verified to be byte-identical 
across all target-AP replays of a matched scenario to enforce the constant 
$O$ required in Section~\ref{sec:problem}).

\subsection{From Trace to Training Data}

In order to train models of particular architectures, we must design appropriate 
representations of the raw captured data. The first representation we use 
is simply the raw trace itself: every decoded frame in order,
carrying its arrival time, channel, BSSID and transmitter, class, flags,
length, signal, airtime, and PHY rate. It is a time series, and we train a
transformer on it directly.

The raw observation is a long sequence, and what distinguishes one AP from
another does not reside at frame granularity. Both problems that arise here
are resolved by binning the time axis and aggregating quantities; As this is possible 
only for features that can be averaged over a set of frames, we define a list of 
hand crafted features. These are enumerated in Appendix~\ref{app:features}.

Aggregation is done per AP before the data is bucketed. Frames are attributed
to an AP by BSSID. Time is bucketed by channel visit: one bin per dwell, so
that no bin spans a retune and aggregates traffic from two channels into a
figure representing neither. A 5.5\,s window against a 110\,ms dwell gives
roughly 50 bins. Each bin carries two sets of quantities: one aggregated over
that AP's own frames, the other over all traffic the radio heard during the
visit. The second is shared by every AP in the choice set, since one radio
hears one channel at a time; a flag records whether the channel being
visited was that AP's own. A transformer attends over bins exactly as it does over frames.

Widening the bucket to the whole window removes time altogether and collapses
everything into a single row of tabular data per AP
(Table~\ref{tab:representations}). AP-specific quantities are
aggregated over that AP's frames alone; channel-specific quantities over the
channel that AP occupies. Gradient boosting, random forests, and ridge regression
are trained on this representation.

Squashing the time axis in this way carries no comparison between options,
since it aggregates over one AP alone: the row records how busy an AP is, not whether it is busier
than its neighbors. A set of relative features is therefore engineered and
appended, restoring for the tabular models the comparison that per-AP
aggregation removed. A sequence or set model needs no such repair, because its
set stage attends across options directly. The cost of leaving the repair out
is visible in Table~\ref{tab:results}: the same binned measurements averaged
over the window, with no relative features, support 0.803 against 0.934 for the
engineered vector, though the two differ in more than the comparison.

The five radio-seed realizations of a topology are near-duplicates, so
train/test splits are cut by topology: letting two of them fall on opposite
sides would inflate every result reported below.

\section{Models, Protocol, and Results}

The dataset holds 6449 AP options across 1500 choice sets drawn from 300
topologies, a median of 4 options per decision. The best option in a set yields
42.6\,Mbit/s on average against 22.0 for one chosen at random, and the best and
worst differ by 35.5\,Mbit/s.

Every decision function below reads the same observation and differs only in
how much of it it is handed. The comparison is between representations as much
as architectures.

\subsection{Baselines}

Three passive baselines are evaluated alongside random selection:

\begin{itemize}
\item \emph{Strongest RSSI} ranks options by mean beacon level.
\item \emph{Least busy channel} ranks them by the clear-channel-assessment busy
  fraction of the channel each occupies, so options sharing a channel are
  indistinguishable to it; tied options are scored at their mean throughput.
\item \emph{RSSI minus busy} maps RSSI from $-100$ to $-60$\,dBm onto the unit
  interval and subtracts the busy fraction from it.
\end{itemize}

\subsection{Learned Models}

Each model reads one representation, and the groups in
Table~\ref{tab:results} say which. Ridge regression, random forests, gradient
boosting, a pointwise MLP and a set ranker read the single-row vector. A
separate set of tabular models reads the binned sequence instead. One
transformer reads the binned sequence and another reads the frame trace; a
third pair reads the vector and the binned sequence together, which is what
measures the trajectory against the averages.

\subsubsection{Tabular Models}

On the vector a tabular model reads one row of 35 numbers per option. The
binned sequence is not tabular, so it is reduced three ways before such a model
can read it: averaged over time, summarised by six statistics per measurement
(mean, spread, extremes, last value and least-squares slope), or handed over
whole with bin order carried by column position. Table~\ref{tab:results} names
these three \emph{averaged over time}, \emph{bin statistics} and \emph{all
bins}. Gradient boosting and a pointwise MLP are
fitted to each of the three, ridge to the flattened one only, every fit a
separate model on a separate input. Both neural models are single hidden-layer
networks; the set ranker scores an option against the rest of its choice set,
the pointwise MLP scores each row alone.

Every model on the vector is selected per split by validation regret: ridge
over regularization strength, gradient boosting over learning rate (0.03 to
0.1), leaf size (4 to 16) and 200 or 400 iterations, the random forest over
leaf size and feature fraction at 400 trees, and the neural models over weight
decay and score temperature. Both tree models also choose whether to fit a
log-transformed target. On the sequence encodings gradient boosting is tuned
the same way; the MLPs there use one fixed setting.

\subsubsection{Transformers}

Both transformers use a model dimension of 48, four attention heads, and
dropout 0.1, and hold roughly $10^5$ parameters. The binned model encodes each
option's sequence with two self-attention layers over bins, reads out a learned
summary token, then compares options with two further layers over the option
set, masked so padding cannot contribute. The frame-level model cannot attend
over the raw sequence directly, since a trace runs to thousands of frames; four
learned queries per option cross-attend into it instead, which is linear rather
than quadratic in frame count. Both are trained with AdamW at $2\times10^{-3}$,
weight decay $10^{-3}$, gradient clipping at unit norm, and early stopping on
validation regret.

\subsection{Protocol}

The learned models divide between two objectives. Regression predicts
$\log(1+\text{throughput})$ in Mbit/s, so its outputs carry a scale. Ranking
learns a distribution over the options in a choice set and optimizes the
decision directly, at the cost of scores that carry no scale. Only the
transformers are run under both.

Each result averages five 60/20/20 partitions of the topologies, stratified by
AP count and redrawn per seed, so test sets overlap and the spread is
draw-to-draw variation rather than a cross-validation error. Every model sees
the same partitions; the frame-level model was run on the first three. Neural
models keep one initialization throughout, so their spread excludes
initialization variance. Model selection uses regret against the oracle choice
on the validation split; the reported metric is top-1 accuracy with a
0.5\,Mbit/s tie tolerance.

\subsection{Results}

Every learned model beats every heuristic, so passive evidence past signal
strength does carry something a client can use. Table~\ref{tab:results} then
reads down the ladder.

Aggregation is not what limits these models. The frame trace, aggregated not at
all, supports 0.897; the binned sequence supports 0.873 under a transformer and
0.847 under the best tabular encoding; averaging those same bins to one row per
option gives 0.803. Collapsing time costs 0.042 for gradient boosting and 0.080
for the pointwise MLP, the one comparison here where a single variable moves
with the model held fixed.

The engineered vector reverses the ordering. It is also one row per option, yet
gradient boosting reads 0.934 from it, ahead of random forests at 0.925 and of
every model given the sequence. Paired by partition, gradient boosting beats the
random forest on all five, by 0.000 to 0.020, so the ordering at the top holds
even though the two standard deviations overlap. What separates 0.803 from 0.934
is not how much of the observation survives but which quantities were computed
from it.

Giving a transformer the vector and the sequence together settles the remaining
question. It reaches 0.931, where gradient boosting already sits with no
sequence at all, so the trajectory adds nothing measurable to the averages.


\section{Interpretation and Next Steps}
\label{sec:next}

The results establish that passive evidence beyond signal strength is useful
for AP selection. They do not establish that the order of that evidence
matters, since a transformer given the vector and the sequence together lands
where gradient boosting on the vector alone already sits.

The simulator gives temporal modeling little to exploit. After background
traffic begins, the ratio of within-series to between-series standard deviation
is 0.09 for frame rate, 0.09 for channel-busy fraction, and 0.17 for the
option's own activity. Most measured variation lies between APs rather than
within an AP over the window. An AP looks much the same at one second as at
five. This is evidence that averaging loses little rather than proof that order
is irrelevant, since a stationary-looking sequence can still carry
autocorrelation, drift, or short-lived events.

The intraclass correlation of 0.988 is not evidence for either representation.
It shows that throughput is highly reproducible once topology and target AP are
fixed across radio seeds, not whether that throughput is best inferred from a
time average, an ordered sequence, or something else.

One reason the sequence alone struggles is sparsity. Under a rotating radio
roughly three-quarters of an option's bins carry no frames from it, because the
radio was listening elsewhere. The vector is computed over the whole window and
does not have that problem, which is a difference in coverage rather than in
what either representation says about time.

The frame-level experiment points the same way. On the three splits both were
evaluated on under the ranking objective, the frame transformer reaches 0.897
against the binned transformer's 0.883, a gap smaller than the spread either
shows across splits. Keeping individual frames buys nothing clear, though only
under traffic as steady as this.

The simulator supports the premise of the project: a client can infer useful
information about AP quality from passive pre-association observation, and
learned combinations of that evidence beat signal strength alone by a wide
margin. What it cannot show is whether order would matter in a network that
moves, since this one barely does. The suggestions below are aimed at that.


\subsection{Suggested Extensions}

Two changes bear on the question this work leaves open. The first is to make
the medium non-stationary on a timescale shorter than the observation window,
and visibly so in a passive trace: load that arrives and departs, stations that
join and leave, interference that appears part-way through. The second is to
shorten the label. A twelve-second mean of an already-stationary process is
predicted best by the window mean, whereas a label measured over the second or
two after the decision gives a trend something to extrapolate toward. Together
they would make the value of temporal order identifiable rather than assumed.

The observation itself could be made more representative. The 802.11 BSS Load
element, which advertises a station count and channel utilisation and which a
client reads from a single beacon, is absent here, and it is the strongest
baseline a real passive client has. The window could also be defined by the
pre-association period rather than by complete silence, admitting the probe
requests most clients actually send.

Two aspects of the scenario generator would repay attention. Channels are
assigned by AP index over a fixed layout, so co-channel separation has no
variance and reuse is tied to deployment size. The effect is a synthetic
shortcut rather than leakage in the usual sense, since the number of discovered
options is legitimately observable: option count determines AP count in 91.8\%
of choice sets, and AP count fixes the channel plan exactly, so a model can read
the reuse regime off the size of its input rather than off radio evidence. The
guard of Section~\ref{sec:problem} checks only that the observation is
independent of which AP is joined, so it does not catch this; sampling the
channel assignment would. Separately, the 30\,m spacing pairs an
obstructed-indoor path-loss exponent with an open-field geometry.


\subsection{Ranking Versus Regression}

The two objectives are not equally testable outside a simulator, and the
difference favors the one this work treats as secondary.

Ranking asks which AP is best. Establishing ground truth for that answer
requires joining each option under identical conditions, which is exactly what 
the matched replay of Section~\ref{sec:sim} provides and what no field
measurement can. A ranking model's output is therefore not easily verifiable 
per decision in the field. Regression on the other hand can be tested reliably 
for accurate predictions of throughput.

This work reports both objectives because the simulator supports both. Work
aimed at deployment should treat throughput prediction as the primary target,
and derive the choice from it, rather than optimizing the choice directly and
inheriting a claim that cannot be checked.
